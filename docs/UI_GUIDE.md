# UI 디자인 가이드

## 디자인 원칙

1. **도구처럼 보여야 한다** — 매일 쓰는 대시보드처럼. 마케팅 페이지가 아니다.
2. **포스트잇이 주인공** — UI 요소는 배경에 녹아들고, 참석자가 만든 콘텐츠(포스트잇)가 시각적 중심.
3. **워크샵 흐름이 보여야 한다** — 현재 어떤 단계인지, 다음에 뭘 해야 하는지 즉시 파악 가능.

---

## AI 슬롭 안티패턴 — 하지 마라

| 금지 사항 | 이유 |
|-----------|------|
| backdrop-filter: blur() | glass morphism은 AI 템플릿의 가장 흔한 징후 |
| gradient-text (배경 그라데이션 텍스트) | AI가 만든 SaaS 랜딩의 1번 특징 |
| box-shadow 글로우 애니메이션 | 네온 글로우 = AI 슬롭 |
| 보라/인디고 브랜드 색상 | "AI = 보라색" 클리셰 |
| 모든 카드에 동일한 rounded-2xl | 균일한 둥근 모서리는 템플릿 느낌 |
| 배경 gradient orb (blur-3xl 원형) | 모든 AI 랜딩 페이지에 있는 장식 |
| "Powered by AI" 배지 | 기능이 아니라 장식. 사용자에게 가치 없음 |

### 랜딩 페이지 (page.tsx)

참석자 위주의 2단계 접속 플로우:

**Step 1 — 초대 코드 입력**

- 코드 입력 후 `GET /api/workshops/preview?code=ABC123`으로 워크샵 정보 조회
- 초대 코드 입력 필드: 대문자만 허용 (A-Z, 2-9). 소문자 입력 시 자동 대문자 변환 (`toUpperCase()`). `maxLength=6`
- 워크샵 제목, description, 현재 단계, 참가자 수 표시
- completed 워크샵: "이미 종료된 워크샵입니다" 안내 + 읽기 전용 참여 가능
- 잘못된 코드: "존재하지 않는 초대 코드입니다" 인라인 에러
- 퍼실리테이터 로그인 링크는 하단에 작게 배치

- 참석자 위주의 단순한 화면. 초대 코드 + 이름 입력이 중심
- 퍼실리테이터 로그인 링크는 하단에 작게 배치

### 단계 네비게이션 (StageNav)

```
[1. 프로세스] ── [2. 수집] ── [3. 클러스터] ── [4. 투표] ── [5. 설계] ── [6. PRD] ── [7. 보고서]
  ✅ 완료       ✅ 완료     🔵 현재위치      ✅ 도달     ⚪ 미도달    ⚪ 미도달    ⚪ 미도달
```

**자유 네비게이션**: 참여자는 도달한 모든 단계를 클릭하여 자유롭게 이동할 수 있다.

- **도달 (열람/편집 가능)**: text-green-500 + 체크 아이콘. 클릭 시 해당 단계 화면으로 전환
- **현재 보기**: text-blue-500 + 원형 인디케이터 (현재 화면에 표시 중인 단계)
- **미도달**: text-neutral-500 + 잠금 표시. 클릭 불가
- **stale (데이터 불일치)**: 도달 단계 중 stale 플래그가 설정된 단계에 ⚠️ 오렌지 도트 배지 표시. stale 표시 기준: cluster 단계는 `clusters.is_stale`, design 단계는 `design_artifacts.is_stale`, generate 단계는 `prds.is_stale`, report 단계는 `ax_reports.is_stale`. context/gather/vote 단계는 AI 산출물이 아니므로 stale 표시 없음
- 연결선: border-t border-neutral-700
- 8단계 (context→completed). completed 시 모든 단계에 체크 표시 (읽기 전용)

**상태 관리**: StageNav는 Zustand `workshopStore`의 두 상태를 참조:
- `currentStage` (DB `current_stage`와 동기화): 최고 도달 단계. 도달/미도달 판정에 사용
- `viewingStage`: 현재 사용자가 보고 있는 단계. StageNav 클릭 시 `setViewingStage(stage)` 호출로 변경
- 초기값: 페이지 로드 시 `viewingStage = currentStage`
- Realtime으로 `currentStage` 전진 수신 시 `viewingStage`도 자동 이동
- 메인 캔버스는 `viewingStage`에 따라 해당 단계 컴포넌트를 렌더링

### Stale 경고 배너
이전 단계에서 데이터가 수정되어 현재 단계의 AI 결과가 최신이 아닐 때 표시.
- **경고 (amber)**: 직접 상위 단계의 수정만 감지된 경우 (예: gather 수정 → cluster stale)
```
rounded-lg bg-amber-900/40 border border-amber-600/50 px-4 py-3 text-amber-200
아이콘: AlertTriangle (lucide, text-amber-400 w-5 h-5)
텍스트: "[상위 단계명] 단계에서 데이터가 변경되어 결과가 최신이 아닐 수 있습니다"
```
- **위험 (red)**: 2단계 이상 상위에서 수정된 경우 또는 다수 stale 플래그 동시 발생 (예: context 수정 → cluster+design+PRD 모두 stale)
```
rounded-lg bg-red-900/40 border border-red-600/50 px-4 py-3 text-red-200
아이콘: AlertTriangle (lucide, text-red-400 w-5 h-5)
텍스트: "여러 단계의 데이터가 변경되어 결과를 다시 생성하는 것을 권장합니다"
```
- 공통 버튼 (퍼실리테이터만):
  - "AI 재실행" — Primary 버튼. 클릭 시 해당 AI 파이프라인 재실행 + stale 해제
  - "현재 결과 유지" — Text 버튼. 클릭 시 PATCH /api/workshops/:id/dismiss-stale 호출 → stale 경고만 디스미스 (AI 재실행 없이)
- 참석자: 동일한 경고 배너 표시 (읽기 전용). 버튼 없음 — 퍼실리테이터만 stale 해제 가능

### 참석자 목록 (ParticipantList)

사이드바 하단에 표시. 현재 워크샵 참석자 목록 + 온라인 상태.

```
┌─ 참석자 (8/20) ──────────────┐
│  🟢 👑 김퍼실 (host)          │  ← 퍼실리테이터: 왕관 + "host" Badge
│  🟢 이참석                    │  ← 온라인: 녹색 도트
│  🟢 박참석                    │
│  ⚪ 최참석                    │  ← 오프라인: 회색 도트
│  ...                         │
└──────────────────────────────┘
```

- 퍼실리테이터: 이름 옆 👑 아이콘 (w-4 h-4) + `host` Badge (bg-amber-900/50 text-amber-300 text-xs). 항상 목록 최상단
- 온라인 상태 도트: w-2 h-2 rounded-full. 온라인 = bg-green-500, 오프라인 = bg-neutral-500. 접근성: `aria-label="온라인"` 또는 `aria-label="오프라인"` + `<span className="sr-only">온라인</span>` 보조 텍스트 (WCAG: 색상만으로 상태를 전달하지 않음)
- 온라인 상태는 Supabase Presence 채널에서 감지
- 이름: text-sm text-neutral-300. 오프라인 시 text-neutral-500
- 참석자 수: 헤더에 "참석자 (현재/최대)" 표시
- 다중 탭 접속 시에도 단일 온라인 표시

### 타이머 (Timer) — Post-MVP (F4)

> **참고**: 타이머는 Post-MVP 기능. MVP에서는 레이아웃 공간만 확보하고 구현하지 않음. 아래는 Post-MVP 구현 시 스펙.

```
┌────────────────────┐
│  ⏱ 08:32           │  ← 카운트다운 (text-lg font-mono)
│  남은 시간           │  ← text-xs text-neutral-500
└────────────────────┘
```
- 퍼실리테이터 설정: 분 단위 입력 (1~60분), "시작" 버튼
- 전원에게 헤더에 카운트다운 표시 (MM:SS, font-mono)
- 0이 되면: text-red-500 + 깜빡임 없이 "00:00" 고정 + Toast "시간이 종료되었습니다"
- 자동 단계 전환 없음 (퍼실리테이터가 수동 전환)
- 동기화: 퍼실리테이터가 타이머 시작 시 presence broadcast로 `{ timer_start: ISO8601, timer_duration_sec: number }` 전송. 다른 참석자가 수신하여 로컬 계산
- 퍼실리테이터 전용: 타이머 설정/시작/초기화 버튼
- 참석자: 카운트다운 표시만 (제어 불가)

| 애니메이션 | 용도 | 설정 |

#### Swimlane
- React Flow `parentId` 메커니즘으로 자식 노드 그룹핑
- 수평 레인: 전체 캔버스 너비, 역할/부서명 좌측 라벨 (세로 텍스트)
- 배경색: 각 레인의 `color` 속성 (반투명, opacity 10%)
- 레인 관리: 사이드바 또는 우클릭 컨텍스트 메뉴에서 추가/편집/삭제/순서변경

#### 하단 노드 팔레트
- 노드 타입별 버튼 → 클릭 시 캔버스 중앙에 노드 추가
- 또는 드래그 앤 드롭으로 원하는 위치에 배치
- 구분: BPMN 요소 | Swimlane | 유틸리티 (자동 레이아웃, 이미지 내보내기)

#### 자동 레이아웃 (elkjs)
- `[📐 Auto Layout]` 버튼 클릭 시 elkjs `elk.layered` 알고리즘으로 노드 위치 재계산
- 방향: left-to-right (수평 프로세스 흐름)
- Swimlane 내 노드는 해당 레인 영역 내에서 배치
- lazy import: 버튼 클릭 시에만 elkjs 번들 로드

#### 노드 위치 저장
- 사용자가 노드를 드래그하여 위치를 변경하면, `onNodeDragStop` 이벤트에서 변경된 position을 API에 PATCH 요청 (debounce 500ms)
- 자동 레이아웃 실행 시에도 모든 노드의 새 position을 API에 일괄 PATCH
- process_steps 테이블에 `position_x`, `position_y` 컬럼으로 저장

#### 이미지 내보내기
- `[📷 Export]` 버튼 → html-to-image로 캔버스 PNG 다운로드
- `getViewportForBounds()`로 전체 그래프 영역 캡처

#### 노드 상세 편집 패널 (NodeDetailPanel)
- 캔버스 우측 슬라이드인 패널 (w-80)
- 노드 클릭 시 열림, 다른 곳 클릭 시 닫힘
- Task 노드: 이름, 설명, 소요시간, 사용도구, 처리량, Swimlane 선택
- Gateway 노드: 이름, 분기 조건 설명
- Event 노드: 이름, 이벤트 유형 설명
- `[저장]` 버튼 → API PATCH + Realtime 전파
- Active 편집자만 편집 가능. Sleep 상태에서는 패널 읽기 전용

#### Active/Sleep 편집 잠금 UI (EditingLockBar)
- 캔버스 상단에 고정 바 (h-10, bg-neutral-800, border-b border-neutral-700)
- **Active 상태**: "✏️ [이름] 편집 중" + 퍼실리테이터에게만 `[회수]` 버튼 표시
- **Sleep 상태 (참석자)**: "[이름]이 편집 중입니다" + `[편집 참여]` 버튼
- **Sleep 상태 (퍼실리테이터)**: "[이름]이 편집 중입니다" + `[회수]` 버튼 (즉시 전환)
- `[편집 참여]` 클릭 → "1초 후 편집 권한이 이전됩니다" 카운트다운 오버레이 (bg-black/60, text-white, 중앙 정렬)
- 전환 완료 시 이전 편집자에게 Toast: "편집 권한이 [이름]에게 이전되었습니다"
- 잠금 없는 상태 (아무도 편집 안 함): `[편집 시작]` 버튼 표시

#### 연결 유효성 검증 (isValidConnection)
- start_event: outgoing 1개만 허용, incoming 불가
- end_event: incoming만 허용, outgoing 불가
- task: incoming/outgoing 각 1개 이상
- gateway: incoming 1개 이상, outgoing 2개 이상
- 셀프 루프 차단 (source === target)

#### 전환 조건
- 최소 1개 프로세스 노드 + start_event 1개 + end_event 1개 등록 후 "다음 단계로" 활성화

## 접근성 (Accessibility)

### 목표
- WCAG 2.1 AA 수준 준수

### 필수 요건

| 영역 | 요구사항 |
|------|----------|
| 폼 입력 | 모든 `<input>`, `<textarea>`, `<select>`에 연결된 `<label>` 또는 `aria-label` 필수 |
| 폼 에러 | 에러 시 input 보더: `border-red-500`. 에러 메시지: 필드 아래 `text-sm text-red-400 mt-1`. 첫 에러 필드에 자동 포커스. `aria-invalid="true"` + `aria-describedby` 연결 |
| 버튼 | 접근 가능한 이름 필수. 아이콘 전용 버튼은 `aria-label` 추가 |
| 모달 | focus trap 필수 (열릴 때 첫 포커스 가능한 요소로 이동, 닫힐 때 트리거 요소로 복귀). Escape로 닫기 |
| 투표 | 키보드(Enter/Space)로 투표 가능. 도트 추가/제거 피드백 제공 |
| StageNav | 키보드로 단계 간 이동 가능 (방향키 또는 Tab) |
| 색상 대비 | 텍스트/배경 대비 최소 4.5:1 (본문), 3:1 (대형 텍스트). 포스트잇 색상은 이 기준 충족 |
| 포커스 표시 | 모든 포커스 가능한 요소에 visible focus ring. `focus-visible:ring-2 focus-visible:ring-blue-500` |
| 상태 알림 | AI 처리 중/완료 상태 변경 시 `aria-live="polite"` 영역으로 알림 |
| 이미지/아이콘 | 장식용 아이콘은 `aria-hidden="true"`. 의미 있는 아이콘은 `aria-label` 추가 |

### 키보드 내비게이션

| 키 | 동작 |
|----|------|
| Tab | 다음 포커스 가능한 요소로 이동 |
| Shift+Tab | 이전 포커스 가능한 요소로 이동 |
| Enter/Space | 버튼 클릭, 투표, 체크박스 토글 |
| Escape | 모달 닫기, 드롭다운 닫기 |
| Arrow Keys | StageNav 단계 전환, 목록 내 이동 |

**단계별 키보드 흐름**:
- **StageNav**: Arrow Up/Down으로 단계 이동. Enter로 선택. 비활성 단계는 건너뜀(`aria-disabled`)
- **투표 화면**: Tab으로 클러스터/노트 간 이동 → Enter/Space로 투표 토글. 남은 투표 수를 `aria-live` 영역에 실시간 안내
- **모달**: Tab으로 내부 요소 순회. Shift+Tab으로 역순. 포커스가 마지막 요소에서 Tab 시 첫 요소로 순환(focus trap)
- **프로세스 그래프(Context 단계)**: tldraw 내부 키보드 지원에 위임. Escape로 편집 모드 해제
- **포스트잇 작성(Gather 단계)**: tldraw 내부 텍스트 입력에 위임. Escape로 선택 해제

### 포커스 관리

- 모달 열림: 모달 내 첫 포커스 가능 요소로 포커스 이동
- 모달 닫힘: 모달을 열었던 트리거 요소로 포커스 복귀
- Toast 알림: 포커스를 빼앗지 않음 (aria-live 영역으로 스크린 리더에 전달)
- 단계 전환: 메인 콘텐츠 영역의 첫 요소로 포커스 이동
- 포스트잇 생성: 생성된 포스트잇으로 포커스 이동 (tldraw 내부 포커스 관리에 위임)

|----------|-------------|----------------|------|
| Chrome (Windows) | NVDA | **P0** — 주력 테스트 대상 | 무료, 가장 널리 사용되는 조합 |
| Edge (Windows) | NVDA | P1 | Chrome과 유사하나 Chromium 차이 확인 |
| Chrome (macOS) | VoiceOver | P1 | macOS 내장 스크린 리더 |
| Safari (macOS) | VoiceOver | P2 — Post-MVP | Safari 특유의 접근성 차이 확인 |

**테스트 시나리오** (P0 — 모든 빌드에서 수동 확인):
1. 랜딩 페이지: 초대 코드 입력 → 이름 입력 → 참여 버튼 (Tab 순서 확인)
2. 모달: 단계 전환 ConfirmModal 열기 → focus trap → Escape 닫기 → 포커스 복귀
3. 투표: 키보드(Enter)로 투표 → aria-live로 남은 투표 수 안내
4. AI 처리 중: pulse 상태에서 aria-live="polite"로 "AI 처리 중" 안내
5. PRD 미리보기: react-markdown 렌더링 결과를 스크린 리더로 순차 탐색

### 복합 컴포넌트 탭 순서

#### VotingCard

```
[1] 클러스터/포스트잇 제목 (읽기 전용 텍스트)
[2] 투표 도트 영역 (role="group", aria-label="내 투표")
  [2a] 도트 1 (button, aria-label="투표 취소")
  [2b] 도트 2
  [2c] 도트 3
[3] "투표하기" 버튼 (남은 투표가 있을 때만 활성)

```

```
[1] 클러스터명 (input, 인라인 편집)
[2] 포스트잇 목록 (각 포스트잇은 읽기 전용)
[3] 요약 통계 (포스트잇 수, 투표 수)
```
