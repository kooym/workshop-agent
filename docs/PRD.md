## 관련 문서

## 목표

고객사의 pain point를 빠르게 실증(PoC/PoV)하여 사업화하기 위한 **비즈니스 엔비저닝 워크샵**을 디지털로 퍼실리테이션하는 웹 어플리케이션.

기존에 포스트잇과 화이트보드로 진행하던 워크샵 프로세스를 온라인으로 옮기고, AI를 활용하여 pain point 클러스터링·AX 설계(TO-BE 프로세스 + Agent 아키텍처)·PRD 생성·종합 보고서 작성을 자동화한다.

## 사용자

### 퍼실리테이터 (Facilitator)
- 워크샵을 기획하고 진행하는 관리자 (1명)
- **Supabase Auth 이메일/비밀번호로 회원가입 및 로그인**
- 로그인 후 대시보드에서 **프로젝트(고객사/사업 단위)별로 워크샵 그룹핑** 조회/관리
- 프로젝트 생성/편집, 워크샵 생성, 단계 전환, 타이머 제어, AI 클러스터링 트리거, 최종 산출물 관리
- 전체 프로세스를 컨트롤하는 관리자 역할
- 세션: Supabase Auth JWT (`@supabase/ssr`로 서버/클라이언트 양쪽 관리)

### 참석자 (Participant)
- 고객사의 다양한 role과 team으로 구성된 사람들 (1~19명, 퍼실리테이터 포함 최대 20명)
- **초대 코드(6자리) + 이름 입력으로 접속. 별도 회원가입 없음**
- pain point/needs 기재, 투표, 피드백 제공
- 각자의 시각에서 업무 프로세스의 문제점과 니즈를 공유
- 세션: HTTP-only 쿠키 (Secure, SameSite=Lax, maxAge=24h). 새로고침 시 자동 복귀

## 워크샵 프로세스 (8단계)

워크샵의 작업 단계는 context → gather → cluster → vote → design → generate → report 순서로 전진하며, 종합 보고서 생성 후에는 `completed` 상태로 전환된다. **참여자는 이미 도달한 단계 사이를 자유롭게 오가며 열람·편집할 수 있다.** 이전 단계로 돌아가 데이터를 수정하면, 하류 AI 결과에 stale 경고가 표시되어 퍼실리테이터가 AI 재실행 여부를 판단할 수 있다. `completed` 상태에서는 모든 산출물을 읽기 전용으로 조회한다.

> **워크샵 목적 설정**: 퍼실리테이터는 워크샵 생성 시 `description`을 입력하여 참석자에게 "오늘 뭘 논의하는지" 맥락을 제공한다. 참석자는 접속 시 워크샵 제목/목적을 확인한 후 참여한다.

### Stage 1: AS-IS 프로세스 정의 (Context)
**목적**: 퍼실리테이터(또는 편집 권한을 받은 참석자)가 현행 업무 프로세스(AS-IS)를 BPMN 그래프로 정의하여, 참석자가 어떤 맥락에서 pain point를 작성할지 구조를 제공

**기능**:
- **프로세스 그래프 에디터**: React Flow 기반 BPMN 그래프로 AS-IS 업무 프로세스 시각화
  - 노드 7종: Task, Start Event, End Event, Exclusive Gateway, Parallel Gateway, Intermediate Event, Sub-Process
  - Swimlane으로 역할/부서별 그룹핑
  - 노드명 (필수, 100자), 설명 (선택, 500자), 소요시간/빈도, 사용 도구/시스템, 처리량/건수
- **자동 레이아웃**: elkjs로 노드 위치 자동 배치
- **Active/Sleep 편집 잠금**: 1인만 편집 가능. 퍼실리테이터 기본 Active, 참석자도 "편집 참여" 버튼으로 Active 획득
- 최소 1개 노드 + start_event 1개 + end_event 1개, 최대 50개 프로세스 노드, 최대 10개 Swimlane
- **참석자 뷰**: 읽기 전용 그래프 (수정 불가. Active 획득 시 편집 가능)
- **이미지 내보내기**: 프로세스 그래프를 PNG로 다운로드
- **단계 진입 안내 배너**: "현행 업무 프로세스를 정리합니다. 시작/종료 이벤트와 업무 단계, 분기를 연결하세요"

**퍼실리테이터 경험**: 워크샵 시작 → AS-IS 프로세스 그래프 작성 (Start → Task → Gateway → Task → End + Swimlane) → 참석자에게 공유 → "다음 단계로" 전환

### Stage 2: 수집 (Gather)
**목적**: 참석자 전원이 AS-IS 프로세스 각 단계에서 겪는 pain point, needs를 기재

**기능**:
- **tldraw 화이트보드** — 실제 워크샵처럼 캔버스에 디지털 포스트잇 생성/이동/편집
- **프로세스 노드 태깅**: 포스트잇 작성 시 또는 작성 후 편집 시 해당하는 AS-IS 프로세스 노드를 선택하여 연결 (선택사항). 생성 시 하단 툴바 드롭다운에서 프로세스 노드를 선택하거나, 생성 후 포스트잇을 클릭하여 편집 모드에서 태깅을 변경/해제할 수 있다
  - 프로세스 노드별 필터링 뷰 제공 (드롭다운: "전체" / 각 프로세스 노드명 / "미태깅"). "미태깅" 선택 시 process_step_id가 NULL인 포스트잇만 표시
  - 태깅되지 않은 포스트잇도 허용 (일반적인 의견/아이디어)
- **멀티플레이어 실시간 동기화** — Yjs CRDT로 20명이 동시에 보드를 보며 각자 포스트잇 작성
- 익명/실명 선택 가능 (퍼실리테이터가 워크샵 생성 시 설정)
- 포스트잇 색상으로 카테고리 구분 (예: pain point = 빨강, needs = 파랑, idea = 초록). **색상 레전드**가 하단 툴바에 표시
- ~~타이머~~ → **Post-MVP** (F4). MVP에서는 퍼실리테이터가 구두로 시간 안내
- **단계 진입 안내 배너** — "각 프로세스 노드에서 겪는 문제점, 필요사항, 아이디어를 포스트잇에 작성해주세요"

**참석자 경험**: AS-IS 프로세스 그래프 확인 → 각 노드별 pain point를 포스트잇으로 작성 → 프로세스 노드 태그 선택 → 다른 사람의 포스트잇 실시간 확인

### Stage 3: 클러스터링 (Cluster)
**목적**: 수집된 포스트잇들을 대주제별로 자동 분류하여 구조화

**기능**:
- **AI 자동 클러스터링**: Azure OpenAI를 활용하여 포스트잇 내용을 의미 기반으로 대주제(클러스터)로 자동 분류
  - 입력: 모든 포스트잇 텍스트 + 프로세스 노드 연결 정보
  - 출력: 클러스터명 + 각 포스트잇의 클러스터 할당 + 클러스터별 요약
- 클러스터 시각화 — 같은 클러스터의 포스트잇들이 그룹으로 묶여 표시
- 클러스터 이름 편집 가능 (퍼실리테이터 전용)
- ~~수동 조정 (드래그앤드롭 이동)~~ → **Post-MVP** (F6)
- ~~클러스터 병합/분리~~ → **Post-MVP** (F6)

**퍼실리테이터 경험**: "클러스터링 시작" 버튼 → AI가 분류 → 결과 확인 → 필요시 수동 조정 → 참석자에게 공유
- **AI 재실행 가능**: 기존 클러스터를 유지하고, 미할당 노트만 재분석

### Stage 4: 투표 (Vote)
**목적**: 클러스터(대주제) 안에서 가장 심각한/중요한 문제점을 참석자 투표로 선별

**기능**:
- **도트 투표 (Dot Voting)**: 각 참석자에게 N개의 투표권 부여 (퍼실리테이터가 설정, 기본 3표)
- **투표 모드 선택**: 클러스터 단위 또는 개별 포스트잇 단위 투표 (퍼실리테이터가 모드 선택)
- 실시간 투표 현황 — 투표 진행 중에는 결과 숨기기 옵션 (앵커링 방지)
- 투표 마감 후 결과 일괄 공개 (바 차트 시각화)
- 투표 결과 기반 자동 순위 정렬
- **투표 참여율 표시** — 퍼실리테이터에게 "N명 중 M명 투표 완료" 표시
- **투표 상태 명시적 표시** — "3표 중 1표 사용" 텍스트 + 도트 인디케이터
- **VotingCard 상세 확장** — 클러스터 모드에서 클릭 시 소속 포스트잇 목록 펼침
- ~~타이머~~ → **Post-MVP** (F4)

**참석자 경험**: 클러스터별 포스트잇 확인 → 중요하다고 생각하는 항목에 투표 → 결과 확인

### Stage 5: AX 설계 (Design)
**목적**: AS-IS 프로세스와 투표 결과를 기반으로, AI가 TO-BE AX 프로세스를 설계하고 Agent 아키텍처, KPI, 데이터/조직 요구사항, AX 과제를 도출

**기능**:
- **AI AX 설계**: AS-IS 프로세스 + 상위 pain point + 투표 결과를 종합 분석하여 6가지 산출물을 동시 생성
  1. **TO-BE 프로세스**: AS-IS 각 단계별 자동화 유형(완전자동/AI보조/사람수행) + Agent 통합 포인트 정의
  2. **Agent 스펙**: Agent별 역할, 핵심/부가 기능, 입출력, Human Checkpoint 정의
  3. **AX 과제**: 과제명, 설명, 연결 pain point, 핵심/부가 기능, 난이도, 예상 효과
  4. **KPI**: AS-IS 현재값 → TO-BE 목표값, 측정 방법
  5. **데이터 요구사항**: 필요 데이터 소스, 형태, 규모, 담당팀
  6. **조직 요구사항**: 협업 체계, 교육, 거버넌스, 인프라 변경 사항
- **과제별 기본 편집** (퍼실리테이터): 과제명, 설명, 난이도 텍스트 편집. ~~core/sub 기능 구조화~~ → **Post-MVP** (F9)
- **참석자 이모지 반응**: 각 과제에 대해 동의(👍) 또는 우려(⚠️) 반응. 1인 1반응, 변경 가능
- **AI 재실행 가능**: 기존 과제 유지 + 새 과제 추가. design_artifacts는 새 버전으로 생성

**퍼실리테이터 경험**: AS-IS/투표 결과 확인 → "AI 설계" 트리거 → TO-BE 프로세스/Agent 스펙/과제/KPI/데이터·조직 요건 검토 → 과제 수정/추가 → 참석자 반응 수렴

### Stage 6: PRD 생성 (Generate)
**목적**: 확정된 AX 과제와 Agent 설계를 기반으로 개발 착수용 PRD를 자동 생성

**기능**:
- **AI PRD 생성**: AX 과제 + Agent 스펙 + TO-BE 프로세스 + 참석자 반응을 종합하여 PRD 초안 자동 생성
  - 출력 구조: 프로젝트 개요 / 목표 / 사용자 / Agent별 기능 상세 / 비기능 요구사항 / 우선순위 / 제외 사항 / 타임라인(선택)
- PRD 실시간 편집 (퍼실리테이터)
- PRD 버전 관리 (수정 이력)
- ~~PDF 내보내기~~ → **Post-MVP** (F11). Markdown 복사는 MVP
- **참석자 이모지 반응**: PRD에 대해 동의(👍) 또는 우려(⚠️) 반응
- **AI 재실행 가능**: 기존 PRD를 새 버전으로 교체 (version+1)

### Stage 7: AX 종합 보고서 (Report)
**목적**: 워크샵 전체 여정의 데이터를 종합하여 경영진과 AX 엔지니어를 위한 종합 보고서를 생성

**기능**:
- **AI 종합 보고서 생성**: 워크샵 전체 데이터(AS-IS 프로세스 → pain point → 클러스터 → 투표 → TO-BE 설계 → Agent 스펙 → KPI → 과제 → PRD 요약)를 입력으로 10개 섹션의 종합 보고서 자동 생성
  - 출력 구조: Executive Summary / AS-IS 분석 / Pain Point 분석 / TO-BE 프로세스 설계 / Agent 아키텍처 / KPI·ROI 분석 / 데이터 요구사항 / 조직 변화 관리 / 구현 로드맵 / 부록
- 보고서 실시간 편집 (퍼실리테이터)
- 보고서 버전 관리
- ~~PDF 내보내기~~ → **Post-MVP** (F23). Markdown 복사는 MVP
- **AI 재실행 가능**: 기존 보고서를 새 버전으로 교체 (version+1)

**퍼실리테이터 경험**: PRD 확정 → "종합 보고서 생성" 트리거 → 보고서 검토/편집 → "워크샵 완료" 버튼

### 단계 전환 사전조건

| 전환 | 사전조건 |
|------|----------|
| context → gather | 프로세스 노드 ≥ 1, start_event 1개 이상, end_event 1개 이상 |
| gather → cluster | 포스트잇 ≥ 5 |
| cluster → vote | 클러스터 ≥ 1 |
| vote → design | 퍼실리테이터가 투표 마감 선언 (전원 투표 필수 아님) |
| design → generate | 과제 ≥ 1 AND design_artifacts 존재 |
| generate → report | PRD 생성 완료 |
| report → completed | 종합 보고서 생성 완료 + 모든 stale 플래그 해제 |

모든 단계 전진 전 ConfirmModal 필수: 현재 단계 상태 요약 표시.

> **자유 네비게이션**: `current_stage`(최고 도달 단계) 이하의 모든 단계는 StageNav에서 클릭하여 자유롭게 이동·열람·편집 가능. 클라이언트는 `viewing_stage`(현재 보고 있는 단계)를 별도 관리하며, StageNav 클릭 시 `viewing_stage`만 변경된다. 이전 단계에서 데이터를 수정하면 `propagateStale(workshopId, modifiedStage)`에 의해 하류 AI 결과에 stale 경고가 전파되며, 퍼실리테이터가 AI 재실행 또는 "현재 결과 유지"를 선택할 수 있다. `completed` 상태는 읽기 전용.

### 참석자 E2E 여정 (Attendee Journey)

참석자 관점의 전체 흐름을 단일 내러티브로 정리한다:

```
1. 초대 코드 수신 (이메일/메신저로 퍼실리테이터가 공유)
2. 랜딩 → 코드 입력 → 워크샵 미리보기 (제목/목적/참가자 수)
3. 이름 입력 → 참여 → 쿠키 발급 → 현재 단계 화면으로 리다이렉트
4. [context] AS-IS 프로세스 그래프 열람 (읽기 전용. "편집 참여" 버튼으로 Active 요청 가능)
5. [gather] 포스트잇 작성 (프로세스 노드 태깅, 색상 선택, 실시간 캔버스)
6. [cluster] AI 클러스터링 결과 확인 (대기 화면 → 결과 자동 반영)
7. [vote] 클러스터/노트에 투표 (N표 소진까지. 결과는 퍼실리테이터 공개 후 표시)
8. [design] TO-BE 프로세스 + 과제 확인 → 이모지 반응(👍/⚠️) 표시
9. [generate] PRD 확인 → 이모지 반응 표시
10. [report] 종합 보고서 확인
11. [completed] 여정 요약 + 내 기여 요약 + 산출물 링크 (읽기 전용)
```

**중간 참여자 (Late Joiner)**: 워크샵이 이미 vote 단계일 때 초대 코드로 접속하면, vote 단계 화면으로 바로 진입한다. 이전 단계(context/gather/cluster)는 StageNav에서 클릭하여 열람 가능하나, 이미 생성된 포스트잇/투표에 대한 수정 권한은 자신의 것만 해당.

**참석자 에러 시나리오**:
- 쿠키 만료 (24시간 후): 랜딩 페이지 리다이렉트 → 동일 코드+이름으로 재참여 (새 participant 생성)
- 네트워크 끊김: Realtime 자동 재연결 → 재연결 실패 시 Toast 경고 → 수동 새로고침
- 브라우저 크래시: 재접속 시 쿠키 유효하면 자동 복구 (Zustand 재페치)

## MVP 범위

### 포함 (MVP)
- F1: 워크샵 생성 (퍼실리테이터 로그인 후, title + description)
- F1.1: 퍼실리테이터 인증 (이메일/비밀번호 회원가입, 로그인, 대시보드)
- F1.2: 프로젝트 관리 (프로젝트 CRUD, 프로젝트별 워크샵 그룹핑)
- F2: 초대 코드 접속 (코드 → 워크샵 정보 확인 → 이름 → 참여, 2단계 플로우)
- F3: 실시간 화이트보드 (tldraw 캔버스 + Yjs 실시간 동기화 + 색상 레전드 + 프로세스 노드 태깅)
- F5: AI 클러스터링 (자동 분류 + 시각화 + 재실행 병합)
- F7: 도트 투표 (기본 3표, 클러스터/노트 모드 선택, 결과 공개, 참여율 표시)
- F8: AI AX 설계 (TO-BE + Agent + 과제 + KPI + 데이터·조직 요건 동시 생성 + 재실행)
- F10: AI PRD 생성 (Agent 설계 기반 PRD + 재생성 버전 교체)
- F13: 세션 복구 (쿠키 기반 자동 복구)
- F14: AI 중복 호출 방지 (처리 중 상태 플래그)
- F15: 입력 검증 (Zod 스키마)
- F16: 참석자 이모지 반응 (과제·PRD에 동의/우려)
- F17: 단계별 안내 시스템 (가이드 배너 + 색상 레전드 + 워크샵 목적 표시)
- F18: 워크샵 완료 여정 요약 (감사 안내 + 전체 흐름도)
- F19: AS-IS 프로세스 그래프 에디터 (React Flow BPMN 그래프 + Swimlane + elkjs 자동레이아웃)
- F20: 프로세스 노드 태깅 (Gather 단계 포스트잇-프로세스 연결)
- F21: Design 산출물 뷰 (탭 기반 TO-BE(Mermaid+React Flow)/Agent/KPI/데이터/조직 표시)
- F22: AI 종합 보고서 생성 (10개 섹션 + AS-IS/TO-BE Mermaid 다이어그램)
- F24: Design 재실행 (기존 과제 유지 + 병합)
- F25: Active/Sleep 편집 잠금 (프로세스 그래프 1인 편집 + 참석자 편집 참여)
- F26: 자유 단계 네비게이션 (도달한 단계 간 자유 이동 + 이전 단계 편집 시 stale 경고)
- 워크샵 8단계 진행 (자유 네비게이션, 전진은 사전조건 필요, 퍼실리테이터가 단계 전진)

### 제외 (Post-MVP)
- F4: 타이머 (분 단위 설정, 브라우저 카운트다운, presence broadcast 동기화)
- F6: 수동 클러스터 조정 (AI 재실행 병합으로 일부 대체)
- F9: 과제 상세 편집 (core/sub 기능 구조화 — 기본 텍스트 편집은 MVP)
- F11: PRD 버전 히스토리 UI / PDF 내보내기 (DB에 버전 보존은 MVP)
- F12: 워크샵 아카이브 (여정 요약 F18로 일부 대체)
- F23: 보고서 편집/내보내기 고급 기능 (기본 편집은 MVP)
- 포스트잇 "좋아요" 리액션 (F16 이모지 반응이 대체)
- 다중 워크샵 동시 진행 (프로젝트당 동시 운영 1개 제한)
- 오프라인 모드
- 모바일 최적화 (데스크톱 우선)
- 녹화/녹음 연동
- SSO/기업 인증 연동

## 디자인 방향
- 다크모드 기본 — 프로젝터/대형 모니터 공유 시 가독성 확보
- 미니멀 대시보드 스타일 — 도구처럼 보여야 함. 마케팅 페이지가 아님
- 색상: 무채색 기반 + 포스트잇 색상으로 포인트
- 반응형은 데스크톱 우선. 태블릿은 참석자 입력용으로만 최소 지원
